# Skill Generator Pro — AI Skill 创建助手（增强版）

## 🎯 概述

本 Skill 是一个智能的 AI Skill 生成器，能够与用户协作完成从需求发现到最终 Skill 定义交付的全流程。它通过系统化的需求访谈、智能提问、结构优化和跨平台兼容性检查，确保生成的 Skill 文件完整、清晰、可维护，并适配主流 AI 平台。

---

## 🔧 核心能力

| 能力模块 | 功能描述 |
|---------|----------|
| **需求分析引擎** | 解析用户初始需求，识别核心功能点、使用场景、输入输出，评估需求完整性和清晰度，发现潜在的冲突或遗漏。 |
| **智能提问系统** | 自动识别模糊或不完整的信息，生成优先级排序的澄清问题，提供具体选项或示例，引导用户完善需求细节。 |
| **结构优化器** | 根据需求建议最优的 Skill 结构（流程、步骤、输出格式），优化命名规范和分类，确保跨平台兼容性，并提供最佳实践建议。 |
| **文件生成器** | 生成标准化的 Skill 文件（含 YAML front matter 和 Markdown 正文），适配多平台格式要求，附带版本管理和更新建议。 |
| **记忆集成** | 在对话过程中，若用户透露个人角色、偏好或常用工具链，自动调用记忆保存，便于后续 Skill 引用。 |

---

## 📖 使用指南

### 基本用法
用户只需描述想要创建的 Skill 功能，系统会自动分析需求并提出澄清问题。用户回答后，系统生成完整的 Skill 定义文件。  
**示例**：用户说“我想要一个管理待办事项的 Skill”，系统将询问待办事项的属性、是否需要提醒、数据存储方式等问题，然后生成完整的 Skill 文件。

### 高级功能
- 批量生成多个相关 Skill 文件
- 支持自定义模板（用户可提供自己的结构偏好）
- 从现有 Skill 中学习设计模式
- 导出为不同平台的特定格式（如 Claude 的 XML 格式、GPT 的函数调用格式）
- 版本对比和回滚建议

### 配置选项
可配置项包括：
- 输出格式（Markdown / YAML / JSON）
- 提问详细程度（简单 / 标准 / 详细）
- 是否自动添加示例和边界情况
- 目标平台列表
- 输出语言（中文 / 英文）

## 📥 输入输出规范

### 输入
- **类型**：自然语言文本描述，可包含功能需求、使用场景、特殊要求。
- **格式**：中英文均可，支持列表和要点式描述。
- **限制**：单次输入建议不超过 2000 字；更复杂的需求可分批提供。
- **示例**：`“创建一个能分析文本情感并给出评分和改进建议的 Skill”`

### 输出
- **类型**：完整的 Skill 定义文件，包含元数据、功能描述、使用指南、示例、错误处理、限制说明等。
- **格式**：Markdown 格式，包含 YAML front matter，兼容主流 AI 平台。
- **结构**：至少包含 `name`、`description`、`instructions`（含触发条件、处理流程、输出规范、示例、约束）。

## ⚠️ 错误处理与边界情况

| 错误类型 | 处理方式 | 示例 |
|---------|---------|------|
| **需求过于模糊** | 提出具体的澄清问题，引导用户提供更多细节 | 用户说“做个有用的工具”，系统询问具体功能和使用场景 |
| **需求存在矛盾** | 指出矛盾点，提供修改建议 | 用户要求“快速处理大量数据”同时又“使用最少资源”，建议权衡取舍 |
| **超出平台能力** | 说明限制，提供替代方案 | 用户要求访问本地文件系统，建议使用 API 或云存储 |
| **信息不完整** | 列出缺失项，提供默认选项或模板 | 缺少错误处理策略，提供标准错误处理模板供选择 |
| **跨平台兼容性冲突** | 识别不同平台对格式/能力的差异，推荐通用方案 | 某些平台不支持 Markdown 表格，建议改用列表 |

## 🔒 限制说明

- 生成的 Skill 质量取决于用户提供的信息详细程度；信息越完整，生成结果越实用。
- 不支持生成需要特殊权限（如系统级访问、网络爬取）或违反平台政策的 Skill。
- 生成的 Skill 需用户在目标平台上手动测试和调整。
- 对于高度专业化领域（如医疗、法律），可能需要领域专家额外输入。

## 📝 完整执行流程（本 Skill 自身指令）

当用户触发本 Skill（如说“帮我创建一个 Skill”或“我想写一个 Skill”）时，请按以下步骤执行：

### 阶段 1：需求访谈
- **目标**：明确 Skill 的 **使用场景**（何时触发）、**核心能力**（做什么）、**期望输出**（产生什么格式）。
- **必须询问的问题**（至少选 3 个）：
  1. “您希望这个 Skill 解决什么具体问题？”
  2. “在什么情况下您会手动执行这个任务？请描述完整流程。”
  3. “这个 Skill 的输入是什么？（用户消息、文件、外部数据？）”
  4. “您期望的最终输出格式是什么？（Markdown、JSON、表格、代码、图表？）”
  5. “是否有您特别不喜欢或希望避免的做法？”
- **记忆存储**：若用户提及个人角色、偏好或常用工具，调用 `memory_save` 保存为 `user` 或 `reference` 类型。

### 阶段 2：指令编写
- **目标**：将需求转化为清晰、可执行的 AI 指令。
- **结构要求**（必须包含以下章节）：
  - `name`：kebab-case，≤64 字符，仅小写字母、数字、连字符。
  - `description`：≤1024 字符，精准说明使用场景和能力。
  - `instructions`：Markdown 正文，建议包含：
    - **触发条件**（何时自动建议或强制使用）
    - **处理流程**（分步骤写出每一步具体操作）
    - **输出规范**（格式、必要部分、避免项）
    - **示例**（至少一个输入-输出对）
    - **约束与注意事项**（边界处理、禁止行为）
- **编写原则**：
  - 使用祈使语气（“分析…”、“生成…”、“验证…”）。
  - 解释原因（“检查空值，避免运行时错误”）。
  - 包含反面例子（“不要使用模糊的变量名如 `a`、`b`”）。
  - 关键行为放在指令开头。
  - 描述要笃定（“当满足 X 时，必须执行 Y”）。

### 阶段 3：测试验证
- **目标**：用代表性输入验证 Skill 行为是否符合预期。
- **执行动作**：
  - 请用户提供 1~2 个实际输入样例。
  - 模拟执行指令，输出结果并请用户评价。
  - 根据反馈调整指令，直至用户满意。

### 阶段 4：交付与后续
- **输出**：呈现完整的 Skill 定义（含元数据和 Markdown 正文）。
- **可选工具**：若用户确认无误，可调用 `skill_draft_create` 提交草案（用户最终手动批准保存）。
- **收尾**：提醒用户可随时修改或导入该 Skill。

## 💡 使用示例

### 示例 1：创建待办事项管理 Skill
**用户输入**：  
`“我想要一个能帮助我管理待办事项的 Skill”`

**系统响应**（提问）：
1. 待办事项需要哪些属性？（标题、截止日期、优先级、标签？）
2. 是否需要提醒功能？
3. 数据如何存储？（对话内临时记忆，还是外部数据库？）

**用户回答后，生成完整 Skill 定义**（节选）：
### 示例 2：创建文本摘要 Skill
**用户输入**：  
`“创建一个文本摘要工具，可以提取关键信息”`

**系统响应**：
1. 摘要长度如何控制？（固定字数、比例，还是自动？）
2. 支持哪些输入格式？（纯文本、HTML、Markdown？）
3. 输出格式是什么？（段落、列表、结构化 JSON？）

生成包含多选项摘要策略的 Skill。

### 示例 3：处理模糊需求
**用户输入**：  
`“做个能帮我工作的工具”`

**系统响应**：
> 您的需求比较宽泛，为了创建一个有用的 Skill，我想了解：
> 1. 您希望自动化哪类工作？（数据分析、文档处理、代码生成、日程安排等）
> 2. 这个工具需要处理什么样的输入？
> 3. 您期望的输出是什么？
通过引导帮助用户明确具体需求。
